## 5. Модель безопасности

- Прилавок — личный инструмент; пишущие эндпоинты открыты по умолчанию.
  Нужен замок — `T5_WRITE_TOKEN` в env: все POST/DELETE требуют
  `x-t5-token` или `Authorization: Bearer` (guard.ts).
- Инбокс: слаги/имена через белые регексы, `..` отсечён, содержимое
  картинок — по магическим байтам, размер ≤25 МБ, X-триаж fail-closed.
- Оракул: 127.0.0.1 + платформенный прокси; лимиты тел; 500-е без
  внутренностей. Caddyfile (`:81` → XTransformPort) — платформенный
  механизм, не трогаем; при публичном деплое закрыть порт-диапазон.
- Секретов в репо нет (аудит 2026-11-20: ghp_/sk-/AKIA/ключи — 0 находок).

5. **Платные LLM-ходы без замка**: `ORACLE_TOKEN` (env) закрывает `/ask`

### 9.1 Инбокс: 502, порции, рейтинг Коула, слот зрением

- **502 шлюза**: тяжёлые multipart-пачки валит Bad Gateway'ем ДО Next —
  клиент теперь режет пачки чанками **≤2 файлов И ≤8 МБ**
  (`upload-chunks.ts`, чистая функция + 5 тестов), каждый чанк — короткий
  POST + один ретрай с паузой 4с на мимолётный 502. Серверный кап
  MAX_BATCH_FILES 40 → 4 (легаси-залпы получают понятный 400).
- **Триаж по 2** (приказ автора): CAP_PER_REQUEST 3 → 2 в обоих роутах.
- **Рейтинг по Коу + слот зрением** (заказ автора): один vision-звонок
  на кадр = дефекты + факт-рейтинг (PG-13/R/R+ · коридор A/B/A+B ·
  one-minute test, гайд docs/RATING-REPAIR-2026-11-13.md) + матчинг
  слота по внешности против сигнатур POS батча. Уверенный матч
  (high/mid) сам заполняет пустой слот файла; ручные теги автора

чанками по 2, КАЖДЫЙ чанк ровно один раз; повторный fail-closed
остаётся карантином до следующего нажатия (автор решает). Тексты
