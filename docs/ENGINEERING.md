**Раскладка контента (важно).** До 2026-11-17 контент жил в `thread5/`
(вложенная копия), прилавок читал её. Затем корпус переехал в корень
репо, а вложенная копия осталась трупом на эре T5-24 — прилавок не видел
T5-25/T5-26, SO-07…10 и 3-значные Y-карты. Апгрейд 2026-11-20:

- `resolveT5Root()` (store.ts): `env T5_ROOT` → `cwd` с `batches/`
  (канонично) → `cwd/thread5` (легаси-раскладка старого сэндбокса);
- вложенное дерево `thread5/` **удалено** (~320 файлов, строгое подмножество
  корня; единственный «уникальный» файл — docx с битой кодировкой имени,
  правильная копия лежит в корне);
- инбокс и Y-чип переехали за контентом (`<T5_ROOT>/inbox`,
  `specs/camera.json` через `readSpecJson` с mtime-кэшем).

## 3. Исправленное в этом апгрейде (реестр фиксов)

**Критическое:**
1. **Y-чип копировал чужое вплетение**: `Y\d{1,2}` в parse.ts резал
   `Y-card: Y513` → `Y51` (все 19 карт T5-26 шли мимо), а заявленный в
   LIVING-NOTES фикс в репо не доехал. Регресс-тест держит.
2. **Прилавок читал труп** (см. раскладку выше) — теперь один источник.
3. **History-навигация**: replaceState → pushState + popstate; Back/Forward
   работают, корректировки — replace.
4. **Гонка загрузки батча** ([ ]/палитра): seq-замок в BatchView.load.
5. **Инбокс терял записи**: read-modify-write meta.json без сериализации →
   `withMetaLock` на всех роутах; клиентские циклы отменяются
   AbortController'ом при уходе со вкладки.
6. **Нулевой слот-парсинг = PASS** в gates.py (живой пример — SO-06,
   шапка разорвана переносом) → FAIL с внятным сообщением.

**Печь (gates.py v1.16.0):** окно Y-карт смотрело вперёд (правка старого
батча ловила WARN от будущих партий) → назад по номеру; depth=0 отдавал
ВСЕ батчи → окно выключено; Corridor-регекс принимал `AB`/`++` и
отваливался от «A + B» → нормализация; сообщения «Y1–Y18» из реликтовой
эры → живой диапазон из camera.json; argv без значений = exit 2 (был
IndexError-трейсбек); краш = exit 3 + баннер (отличим от FAIL); квитанция
пишет путь относительно корня (sha-замок не слеп от чужого CWD); mkdir
для --md; stdout не падает на кириллице в cp1251-пайпе; SO-батчи не
шумят story-cards WARN'ом; слоты/расы/ходы P/R/M 100+ парсятся.

**Вкус и окно:** taste.py брал ПЕРВЫЕ вердикт-секции вместо последних
(свежайший вкус не доезжал до SOL) → `take_recent` (сейчас в корпусе
ровно 3 секции со structured-квитанциями, поэтому инверсия была
невидима — тест фиксирует на будущее); window.py сортировал по mtime
(врёт после правок) → по номеру партии; убран walrus с двойным поиском.

**Прилавок:** Escape при открытой палитре/лайтбоксе выкидывал из батча →
гард по `paletteOpen` + `[data-t5-overlay="open"]`; DocsView терял кэш
на каждом уходе со вкладки → модульный Map; спец-заказы падали в общем
catch загрузки → мягкий readJson + тост; битый localStorage валил рендер
копировалки → валидация формы; таймеры копирования не чистились → refs;
ключи секций актов могут дублироваться → индекс-префикс; hotkey-эффект
переподписывался каждый рендер → ref-паттерн; тосты жили 16 минут в
памяти → 5 с; лайтбоксы получили фокус-трап/скролл-лок/возврат фокуса и
клещование индекса; ретрай загрузки инбокса не дублирует файлы (чанки
вычёркиваются по факту); «хоть все 33 разом» → честные 40.

**API:** опциональный `T5_WRITE_TOKEN` (не задан — поведение прежнее);
`..`-гварды в путях инбокса; verdict-штамп с секундами (два вердикта в
минуту не затираются).

**Оракул:** слушает 127.0.0.1 (env ORACLE_HOST/PORT); /audit не падает
от нестрокового pos (400 вместо TypeError-500); Object.hasOwn —
`?card=constructor` не возвращает фантом; /dataset с mtime-кэшем и
счётчиком битых строк; лимиты /ask 32k, /vision ~8 МБ + mime-whitelist;
персона — системным ходом; 500-е не светят внутренности. Деплой:
knowledge-пак копируется рядом с бандлом (ENOENT на старте), контент
копируется в standalone-артефакт (`/api/t5/*` в проде отвечал пустотой).

**Датасет/тренинг:** генераторы a–d писали в CWD (build.py молча строил
меньше) → рядом со скриптом; build.py — контекст-менеджеры, пропуск
битых строк со счётчиком, явный отказ при отсутствующих частях;
train_lora.py — compute-dtype по факту GPU (жёсткий bf16 ронял T4),
CUDA-гард; requirements — верхние границы (TRL ломает API между
минорками); eval_oracle --fallback — X-order проба раньше всегда FAIL.

**Валидатор:** REQUIRED_GATES_KEYS догнан до 1.15.0 (10 секций, чьё
отсутствие молча выключало гейты); рекурсивная компиляция всех
конфиг-регексов (битый паттерн ронял gates в трейсбек на живом прогоне);
camera.json — y_cards непуст и id в форме Y{1,3}; `--ci` /
`T5_VALIDATE_CI=1` — без проверки хука; pre-commit: квитанция по имени
(sort -V), чтение с encoding='utf-8', путь через sys.argv.

## 5. Модель безопасности

- Прилавок — личный инструмент; пишущие эндпоинты открыты по умолчанию.
  Нужен замок — `T5_WRITE_TOKEN` в env: все POST/DELETE требуют
  `x-t5-token` или `Authorization: Bearer` (guard.ts).
- Инбокс: слаги/имена через белые регексы, `..` отсечён, содержимое
  картинок — по магическим байтам, размер ≤25 МБ, X-триаж fail-closed.
- Оракул: 127.0.0.1 + платформенный прокси; лимиты тел; 500-е без
  внутренностей. Caddyfile (`:81` → XTransformPort) — платформенный
  механизм, не трогаем; при публичном деплое закрыть порт-диапазон.
- Секретов в репо нет (аудит 2026-11-20: ghp_/sk-/AKIA/ключи — 0 находок).

## 6. Известные ограничения (осознанно не тронули)

- Prisma/next-auth из шаблона платформы не убраны: `.zscripts`
  собирает рантайм БД вокруг них; прилавок их не использует.
- Кэш прилавка — in-process: в standalone-деплое инбокс/вердикты живут
  на диске одного инстанса (горизонт не предполагается).
- eslint-конфиг остался мягким (правила шаблона отключены) — включение
  strict-режима требует чистки ui/компонентов шаблона, не ядра.
- `reactStrictMode: false` — включение потребует чистых апдейтеров
  во всех пасхалках (частично сделано в juice.tsx этим апгрейдом).

## 8. ECCHI-ORACLE-2: нервная система (апгрейд 2026-11-20, вечер)

> Полная карта — `docs/ORACLE.md`. Здесь — дельта к архитектуре и реестр
> фиксов второго инженерного раунда.

**Что изменилось в архитектуре (§1):** новый канонический движок
`src/lib/t5/oracle-engine.ts` (чистый TS, ноль зависимостей) — его
импортируют и прилавок, и oracle-service (bun build инлайнит в бандл);
печь получила побитовое python-зеркало `tools/oracle.py`. Паритет лочат
золотые векторы `tests/fixtures/oracle_vectors.json`, которые читают оба
тестовых набора. Жребий детерминирован: seed = номер партии; живая сверка
трёх органов на T5-27 дала побитово один расклад.

**Новые поверхности:** вкладка «Оракул» (клавиша 5, циан `--t5-oracle`):
пульс сервиса · жар последних 6 партий · жребий с копированием в бриф ·
экспресс-оценка любого текста. API: `/api/t5/oracle/{status,heat/[slug],
draw,rate}`. Сервис: `POST /batch` (агрегированный аудит партии), `GET
/window`, `GET /draw`. Печь: `oracle.py {status,window,draw,heat,audit,
selftest}`. Полоска жара — в шапке каждого батча. Командная палитра: «Оракул»
и «Жребий на следующую партию». Хоткеи вкладок: 1–5.

**Реестр фиксов этого раунда:**

1. **parse_for жрал все цифры строки**: «T5-27» → 527 — жребий печи сеялся
   не тем номером и расходился с сервисом (поймано живой сверкой органов).
   Регресс-тест в test_oracle_tool.py.
2. **repoRoot() в сервисе брал dirname от specs/camera.json** → `specs/`,
   а не корень: `/window` и `/draw` видели пустой корпус (0 партий).
   Теперь два уровня вверх.
3. **/rate принимал неограниченный текст** (остальные лимиты были) → 20k,
   паритет с /audit; /triage — 20k; /volt — обрезка полей 500/8/8;
   /batch — ≤100 слотов.
4. **/audit падал от нестроковых badge/corridor/card_id** (число в поле →
   TypeError-500) → коэрция String() на всех входах аудита.
5. **Платные LLM-ходы без замка**: `ORACLE_TOKEN` (env) закрывает `/ask`
   и `/vision` (заголовок `x-oracle-token` / Bearer); `/health` показывает
   `llm_lock`. По умолчанию выключен — поведение прежнее.
6. **build_window(синтетика) не сортировала корпус** (живой был
   отсортирован) → сортировка по номеру всегда.
7. **ПРОД-БАГ прошлой волны — резолвер путей в бандле**: деплой кладёт
   knowledge-пак РЯДОМ с бандлом (mini-services-dist/ecchi-oracle) и
   контент в next-service-dist/, а сервис искал только раскладку репо
   (../ecchi-oracle, ../../specs) — прод-бандл падал в ENOENT на старте
   либо молча сидел на устаревшем fallback-реестре таксономии.
   Кандидаты расширены (пак-рядом-с-бандлом и next-service-dist первые
   после env), деплой-раскладка проверена живым бандлом: реестр 1.16.0,
   521 карт, окно видит корпус, жребий побитово тот же.

8. **Жар-честность на прозе В35 врала** (поймано дымом прилавка):
   тег-словари lite не читают прозаические заявки → ложный дрейф 33/33 на
   T5-26. Честность переведена на два базиса: карточные слоты — вплетение
   1:1 (реестровое), бескарточные — lite только при юрисдикции (≥1
   сигнального тега); ноль сигналов = «проза вне словарей», не дрейф.

**Тесты (дельта):** +38 bun (`tests/unit/oracle.test.ts`: векторы жребия,
mulberry32, rateTextLite, окно, история, жар) · +19 python
(`tests/python/test_oracle_tool.py`: те же векторы, регресс parse_for,
selftest CLI) · CI: пайплайн-джоба гоняет `oracle.py selftest` отдельным
шагом. Итого: 84 bun + 36 python.

**Осознанно НЕ стали делать:** третье зеркалирование словарей оценки в
python — честность label↔fact в печи берётся у сервиса (без сервиса
компонент нейтрален и помечен n/a); единый конфиг квот жребия в specs/
(пока цели в аргументах CLI/запроса — квоты партии решает автор).
