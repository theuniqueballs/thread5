# ПРОТОКОЛ ТОКЕНА ДОСТАВКИ (fine-grained PAT) — thread5, 2026-11-25

Аудит 5.3 §2.1 («PAT-ритуал доставки»), решение автора №7: перейти на
fine-grained токен — да, но только с понятным и безопасным протоколом.
Документ — сам протокол. Менять его без автора нельзя.

## Факт, из которого всё растёт

Branch protection на `main` исключает интеграционный push, каждая доставка —
ручной push с токеном. Фактический носитель секрета сегодня — чат-транскрипт.
Полностью убрать секрет из чата из песочницы нельзя (пуш делает агент);
можно минимизировать радиус взрыва, если токен утечёт.

## Что за токен

**Fine-grained PAT** — личный токен GitHub с ограничением ПО РЕПОЗИТОРИЮ,
ПО ПРАВАМ и ПО СРОКУ одновременно. Классический `ghp_…` действует на все
репо аккаунта со всеми правами — именно его радиус и пугает.

## Создание (руки автора, ~2 минуты, всё на github.com)

1. GitHub → Settings → Developer settings → Personal access tokens →
   **Fine-grained tokens** → Generate new token.
2. Token name: `thread5-delivery`. Expiry: **30 дней** (ротация по календарю).
3. Repository access: **Only select repositories** → `theuniqueballs/thread5`.
   Никаких «All repositories».
4. Permissions → Repository permissions → **Contents: Read and write**.
   Всё остальное — No access (Metadata: Read-only проставится сам).
5. Generate → скопировать токен (`github_pat_…`).

## Где токен живёт и где НЕ живёт

- **Живёт**: у автора — в credential-хранилище машины (`git config
  credential.helper manager` / Keychain / `gh auth login`) ЛИБО в чате
  ровно на время сессии доставки.
- **НЕ живёт**: в файлах репо (любых), в коммит-сообщениях, в `.git/config`
  дольше одного пуша, в скриншотах, в квитанциях, в логах тестов.

## Ритуал пуша из песочницы (уже действующий, tighten'ся протоколом)

```bash
git remote set-url origin https://<ТОКЕН>@github.com/theuniqueballs/thread5.git
git push origin main
git remote set-url origin https://github.com/theuniqueballs/thread5.git
```

Токен живёт в `.git/config` СЕКУНДЫ (три команды одним прогоном), после —
затирается. Проверка после пуша (обязательная):

```bash
rg -n "github_pat_|ghp_" .git/config          # пусто
git log -S "github_pat_" --oneline --all      # пусто (никогда не был в истории)
```

## Ротация и отзыв

- **30 дней** — истёк сам; новый создаётся за 2 минуты по этому же протоколу.
- **Любое подозрение** (токен засветился в скриншоте/чужом логе/переписке) —
  немедленно: Settings → Fine-grained tokens → **Delete**. Радиус: один репо,
  один права-набор, ничего больше не ломается.
- Проверка использования: Settings → Audit log → фильтр по имени токена
  (`thread5-delivery`) — видно каждый push.

## Почему радиус мал (ответ на «боюсь, что улетит»)

Утекший fine-grained токен даёт: запись В ОДИН репозиторий, contents-only,
до конца срока (≤30 дней) или до мгновенного Delete. Он НЕ даёт: другие
репо, settings, Actions-правки, удаление репо, доступ к аккаунту. Худший
сценарий — грязный коммит в `main`, откатывается форс-пушем за минуту
плюс Delete токена. Это на порядки мягче классического `ghp_…`.

## Вариант Б (строже, по желанию автора)

**Deploy key** (read/write) — SSH-ключ, привязанный к ОДНОМУ репо, вообще
без user-scope: Settings → Deploy keys → Add deploy key (+ Allow write
access). Идеален для машинных пушей; не даёт API, но агент пушит обычным
git — хватает. Если выбран — протокол пуша меняется на `git@github.com:…`
remote, токен исчезает из чата вовсе.
