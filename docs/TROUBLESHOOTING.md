# TROUBLESHOOTING — топ-ошибок цеха (тройной вердикт 2026-11-22, P3)

Короткие рецепты. Подробная механика — ENGINEERING.md; законы — LAWS.md.

## Гейты

**Гейт FAIL на свежей партии.**
Читай `batches/T5-NN.gate-report.md` (или stdout гейтов): каждая строка
ошибки называет слот и закон. FAIL > 10 — чини EARTH/SOL (сборку), не
добавляй «ещё гейт». Типовые: разорванная шапка слота переносом строки
(парсер видит 0 слотов — мгновенный FAIL BATCH), claim не в первых
токенах, ложный бейдж R+ (В43: состав кадра не несёт R+).

**«Y-STAMP (режим: FAIL-эра)» при вердикте PASS — это не ошибка.**
Это метка ЭРЫ гейта (с T5-25 метки-паспорта в POS = FAIL), а не
результат проверки. Результат — строка «ВЕРДИКТ: PASS · FAIL: 0».

**Батарея красная сразу после чекаута на СТАРОМ рабочем дереве.**
Чекаут, материализованный ДО `.gitattributes` (например, Windows с
`core.autocrlf=true`, сделанный до 2026-11-27), держит CRLF-копии
текстовых файлов без единого реального дрейфа контента. Тесты
платформенной честности (тикет #1) гоняют синтетические копии из
контента в памяти и на это не падают, но живое дерево остаётся CRLF.
Лечится одним из:
`git rm -r --cached . && git reset --hard` (перематериализовать дерево
по .gitattributes) или свежий клон. Проверка: `git ls-files --eol |
head` — рабочие файлы текстовых семейств должны показывать `w/lf`.

**Изменённый батч не коммитится (sha-замок).**
Перегенерируй квитанцию ТЕМ ЖЕ коммитом:
`python3 tools/gates.py batches/T5-NN.md --json specs/gate-receipts/<дата>-T5-NN-vNN.json --md batches/T5-NN.gate-report.md`
Untracked-квитанции тоже блокируют (1.11a) — `git add` их.

## Валидатор

**validate.py FAIL «y-trust.json отстаёт от verdicts/*.json» (№15).**
Добавлен/изменён JSON-вердикт — пересобери траст-слой:
`python3 tools/oracle.py trust --rebuild`.

**validate.py FAIL «нет записи для T5-NN» (№12).**
Каждый T5-*.md в batches/ обязан иметь статус в
specs/delivery-index.json (draft/ready/delivered/superseded).

**Кириллица/кодировка.** Все инструменты печатают с
`errors="replace"`; если консоль Windows роняет вывод — chcp 65001.

## Оракул

**Сервис не отвечает (порт 3031).**
`python3 tools/oracle.py status`; подними мини-сервис:
`cd mini-services/oracle-service && bun install && bun run dev`.
CLI печи (`pool/draw/heat/window`) работает и без сервиса; паритет
лочат золотые векторы (`oracle.py selftest`).

**Жребий «иссяк» (shortfall > 0).**
Окно ротации + запрет поз съели пул. Смотри `oracle.py pool --for T5-NN`;
пул ниже target 60 — сигнал SOL'у (тема не должна требовать экзотики).

**Траст-пул пуст / нет HIGH.**
Карты из loved сидят в окне ротации — это нормально после вердиктной
партии; HIGH выйдут из окна через 3 партии. LOW не возвращаются сами —
только новый хит (вердикт) или LAB.

## Прилавок

**Не запускается.** `bun install && bun run dev` (порт 3000). В деплое —
за Caddy (:81 → 3000). БД не нужна (Prisma вырезан 2026-11-23).

**Инбокс не видит файлы.** Форматы: webp/png/jpg, до 25 МБ, магические
байты проверяются; имя файла с `..` отсекается. Журнал: `<T5_ROOT>/inbox/`.

**Пишущие эндпоинты открыты.** Прилавок — личный инструмент. При
публичном деплое обязательно задай env `T5_WRITE_TOKEN` (guard.ts) и
закрой порт-диапазон.

## Тесты / CI

**Юнит-тесты печи падают.**
`python3 -m unittest discover -s tests/python -v`. Тесты coverage
работают во временном корпусе — боевой coverage-ledger.json они не
трогают (если трогают — это регресс бага №1, смотри test_cycle4).

**bun test падает в CI, локально зелёный.** CI ставит зависимости
`bun install --frozen-lockfile` — lockfile обязан быть свежим
(коммить bun.lock вместе с package.json).

**CI pipeline FAIL на гейтах свежайшей партии.** CI берёт партию из
`tools/t5delivery.py latest` (delivery-index), не из ls — убедись, что
статус партии correctен (готовая к сдаче = ready, сдана = delivered).

## Тест-горн

**testforge check ругается на болванки proto 1.** Это era-skip
(«история не переписывается»): болванки до PROTO-2 не бьются новыми
законами. Реальные нарушения — только у proto 2.

**coverage-счётчики подозрительно большие.** С 2026-11-23 coverage
пересчитывается с нуля (копилка вылечена). Сумма y_cards обязана быть
ровно числу слотов корпуса; если растёт — регресс, см. баг №1.
