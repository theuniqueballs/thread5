# ПЛАН 5.5 «ПРАВДА В КАДРЕ» — реконструкция после T5-34

Статус: черновик внешнего соавтора (аудитора), 2026-11-27.
Основание: вердикт T5-34 («ты нигде рейтингом не попал… единственное что

(В51–В56), онбординг-документ THREAD 5 (10 зон боли).

## 0. Диагноз одной строкой

Машина научилась **проходить собственные гейты** и разучилась **попадать
в кадр**: гейты мерят бумагу (токены POS, жанровые метки), пиксели видит
только автор — и в T5-34 это стоило 15 ложных R+ из 17.

Следствие: у системы нет контура «факт». Пока факт-слой не построен,
любая perfection бумажных гейтов — полировка дрейфа.

## 1. Цели-числа (KPI реконструкции)

| Метрика | T5-34 (факт) | Цель T5-35 | Цель T5-37 |
|---|---|---|---|
| R+-заявок, доехавших до рендера (fact-hit) | 2/17 (12%) | ≥ 50% | ≥ 70% |
| Ложных R+ (label ≠ fact) | 15/17 | ≤ 7 | ≤ 3 |
| Тема читается на рендере (мейны) | 1/31 (3%) | ≥ 60% | ≥ 75% |
| OC-fidelity (канон-локи на месте) | 1/3 катки SO-19, очки SO-20 | 3/3 | 3/3 + 2 SO |
| X-слип | 0 | 0 (держать) | 0 |
| NICHE в тир ±1 | 8/10 | ≥ 8/10 | ≥ 9/10 |
| Ghost-статусы / hotfix после «муха не еблась» | 0 / 2 | 0 / 0 | 0 / 0 |

KPI считаются ПОСЛЕ вердикта, из rating_truth_delta + render-QC — никогда
из гейт-отчёта (закон «гейты чисты ≠ муха не еблась», AGENTS №8).

## 5. Риски / что может пойти не так

- **render-QC привязка по канон-локам** — уже падала на коллизиях (T5-17,
  T5-33): renderqc.py наследует урок «пин по исключению не ставится»,
  спорные файлы — автору.
- **VLM-тираж** — счёт токенов/квот: renderqc.py обязан работать пачками
  с ретраем и честным «не разобрано», не карантином всего инбокса (урок
  401-инцидента T5-33).
- **Перелейка старых карт ≠ новая волна** — это пересборка существующих
  id, реестр не растёт (закон реестровой диеты 5.3).
- **Сложность-бюджет сам станет сложностью** — гейт-счётчик в квитанции,
  НЕ новый реестр и НЕ новая доктрина.
