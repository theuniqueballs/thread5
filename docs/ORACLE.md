## 1. Три органа, одна нервная система

```
                    ┌────────────────────────────────┐
                    │  src/lib/t5/oracle-engine.ts   │
                    │  КАНОНИЧЕСКИЙ ДВИЖОК (чистый   │
                    │  TS, ноль зависимостей):       │
                    │  · rateTextLite (оценка)       │
                    │  · batchHeat (жар)             │
                    │  · buildRotationWindow (окно)  │
                    │  · drawConstellation (жребий)  │
                    └──────┬──────────┬──────┬───────┘
                           │ импорт   │ импорт│ зеркало (python)
              ┌────────────▼──┐  ┌────▼─────────┐  ┌─▼──────────────┐
              │ ПРИЛАВОК      │  │ СЕРВИС :3031 │  │ ПЕЧЬ           │
              │ вкладка       │  │ /batch /draw │  │ tools/oracle.py│
              │ «Оракул» +    │  │ /window      │  │ window/heat/   │
              │ API-роуты +   │  │ + LLM/vision │  │ draw/audit/    │
              │ полоска жара  │  │ (усилитель)  │  │ status/selftest│
              └───────────────┘  └──────────────┘  └────────────────┘
                     │                  │                  │
                     └────────┬─────────┴────────┬─────────┘
                              ▼                  ▼
                 tests/fixtures/oracle_vectors.json
                 ЗОЛОТЫЕ ВЕКТОРЫ: bun-тест и python-самтест
                 читают один файл — паритет лочен с двух берегов
```

**Правило выживания:** прилавок считает всё локально (движок в бандле);
сервис — усилитель (LLM-мозг `/ask`, зрение `/vision`, полный аудит с
x_risk_drivers). Сервис лежит — прилавок не ломается, печь не ломается,
вкладка честно показывает «локальный режим».

## 2. ЖРЕБИЙ ОРАКУЛА — детерминированный расклад карт

**Задача:** к следующей партии (T5-27) оракул тянет констелляцию Y-карт:
3 OC + 21 мейн + 9 EXP — окно ротации чисто, коридоры сбалансированы,
новенькие в приоритете.

**Механика** (`drawConstellation` в oracle-engine.ts):

- **seed** = номер партии × 2654435761 mod 2³² (Knuth) → `mulberry32`;
  тот же номер партии + тот же корпус → тот же расклад. Всегда. В прилавке,
  в печи и в сервисе — побитово (живая сверка 2026-11-20: OC `Y443 Y351
  Y486`, мейн `Y333 Y261 Y301 …` — совпали все три органа);
- **окно ротации** (глубина 3, как `y_assembly.window`): карты последних
  трёх партий НЕ раздаются (T5-27 не увидит 57 карт из T5-24/25/26);
- **OC-тройка**: корзина коридора A/A+B, класс COVER в приоритете,
  свежесть решает («новенькая» → «давненько не была»);
- **мейн-лента**: круглый обход корзин [A, B, низкие тиры] — баланс
  коридоров партии; A+B живёт в двух корзинах сразу;
- **EXP-волна**: только никогда не использованные, старшие номера первыми
  («новенькие Y которых ещё не создавали» — заказ автора T5-26);
- rng тратится в ЖЁСТКОМ порядке — по одному вызову на слот, никаких
  rng-тайбрейков в сортировках: иначе питон-зеркало разъедется с каноном.

**Зеркала и паритет:**

| Орган | Реализация | Чем лочена |
|---|---|---|
| прилавок | `oracle-engine.ts` (канон) | `tests/unit/oracle.test.ts` |
| сервис | импорт того же `oracle-engine.ts` (bun build инлайнит в бандл) | теми же векторами |
| печь | `tools/oracle.py draw_constellation` (побитовое зеркало, беззнаковая 32-бит арифметика) | `python3 tools/oracle.py selftest` + `tests/python/test_oracle_tool.py` |

Правка алгоритма = перегенерация векторов (`bun tools/make_oracle_vectors.ts`)
+ синхронное обновление обоих зеркал. Векторы живут в
`tests/fixtures/oracle_vectors.json` (синтетический реестр на 30 карт —
живой корпус на паритет не влияет).

## 3. ЖАР ПАРТИИ — метрика здоровья

`batchHeat` (прилавок: `/api/t5/oracle/heat/[slug]`; печь: `oracle.py heat`):

```
жар = 0.30·R+-доля      против коридора плана [0.30..0.60]
    + 0.20·баланс коридоров  (min(A,A+B)/max(B,A+B))
    + 0.20·свежесть карт     (не использованные до партии / карты в слотах)
    + 0.15·честность label   (дрейф label↔fact по lite-движку)
    + 0.15·уникальность каналов (деловые повторы = штраф)
```

≥75 — ГОРЯЧО · ≥50 — ТЁПЛЫЙ · ниже — ХОЛОДНЫЙ. Живой замер T5-26:
**79/100 ГОРЯЧО** (R+ 58%, A×19, 19/19 карт свежие, честность 19/19 по
вплетению + 1 словарный дрейф).

**Честность — два базиса (урок замера T5-26):** слот с Y-картой честен
ВПЛЕТЕНИЕМ 1:1 (реестровое — тег-словари прозу В35 не читают и давали
ложный дрейф 33/33); бескарточный слот судится lite-словарями ТОЛЬКО при
юрисдикции — в POS есть хоть один сигнальный тег. Ноль сигналов =
прозаявка вне словарей → не дрейф, а пометка «проза вне словарей». Ретро-
партии до В34 честно показывают weave-missing: клеймо тогда было меткой.

**Это эвристика, не вердикт.** Гейты проверяют контракт слота, автор
выносит вердикт; жар — «как себя чувствует конвейер» одним числом:
полоска в шапке батча (прилавок), `/api/t5/oracle/heat/[slug]`, `oracle.py
heat batches/T5-26.md`. В печи честность label↔fact берётся у сервиса
(если поднят); без сервиса компонент нейтрален и помечен `n/a` — словари
оценки живут в TS, тройное зеркалирование словарей запрещено осознанно.

## 4. ОЦЕНКА — четыре режима, каждый подписан (двойной аудит 2026-11-20 P1-05:
пользователь видит одну оценку локально и другую в сервисе — и считает это
багом; лечится явной подписью режима, а не сведением движков в один)

| Режим | Где живёт | Что умеет | Чего НЕ умеет |
|---|---|---|---|
| **LOCAL-LITE** | `rateTextLite` (oracle-engine.ts, прилавок без сервиса) | тир/коридор/классы/флоры/WARN мгновенно и бесплатно | расширенные словари, x_risk_drivers, полный аудит |
| **SERVICE-RULE** | oracle-service `POST /rate` (полный rule-engine) | всё lite + x_risk_drivers + WARN-флоры + аудит | смотреть картинку |
| **VISION-ASSIST** | инбокс-разбор (`/vision` через сервис) + оракул-факт-рейтинг кадра | дефекты, факт-рейтинг по гайду Коула (бейдж ≠ факт), слот зрением | не вердикт: подсказка автору |
| **AUTHOR-VERDICT** | автор, после рендера (verdicts/*.json — канон) | всё: красота, вкус, канонизация | — |

Любой результат Oracle в UI несёт: режим, версию движка (ENGINE_ERA) и
подпись «метрика ≠ вердикт качества» — финальный судья один (LAWS §9).

Экспресс-оценка без сервиса: тир (SFW/PG-13/R/R+/X), коридор
(A/B/A+B/NONE), классы раскрытия (COVER/PROCESS/LINGERIE/CLOTHED-TIGHT/
SHEER), FAIL-флоры (anti-loli, XXX, genital_lock, muscle_law, milf),
WARN-подсказки (мёртвая ткань, sheer без bare-under, R+ без коридора).

- прилавок: вкладка Оракул → «Экспресс-оценка» (⌘/Ctrl+Enter), POST
  `/api/t5/oracle/rate` — lite локально + полный вердикт сервиса, если жив;
- сервис: `POST /rate` — полный движок (x_risk_drivers, WARN-флоры).

Зеркальная дисциплина: словари lite = подмножество словарей сервиса;
вердикт/коридор/классы обязаны совпадать на любом входе (векторные тесты
держат; расхождение = баг либо здесь, либо в сервисе). Совпадать обязаны
там, где оба работают; разница — только в глубине, и она подписана режимом.

## 6. Безопасность (дельта ORACLE-2)

- `ORACLE_TOKEN` (env): замок ПЛАТНЫХ эндпоинтов сервиса (`/ask`, `/vision`)
  — не задан, поведение прежнее; задан — нужен заголовок `x-oracle-token`
  или `Authorization: Bearer`. `/health` честно показывает `llm_lock`;
- лимиты тел: `/rate` `/audit` `/triage` 20k · `/volt` поля 500/8/8 ·
  `/batch` ≤100 слотов по 20k · `/ask` 32k · `/vision` ~8 МБ (было: `/rate`
  принимал неограниченный текст — закрыто);
- `/audit`: нестроковые `badge/corridor/card_id` коэрцируются — число в
  поле больше не роняет сервис в TypeError-500;
- прилавок: все новые роуты только читают (GET/POST без записи на диск) —
  write-token не требуется.

## Траст-слой Y (2026-11-23, Коул §7 + заказ автора)

`specs/y-trust.json` — генерируемый реестр доверия: HIGH (хит в
JSON-вердикте — loved или подтверждённая гипотеза) / MID (нет улик или
только ok_with_issues) / LOW (катана мимо loved/ok). Хит сильнее промаха.

```bash
python3 tools/oracle.py trust --rebuild   # после каждого нового verdicts/*.json
python3 tools/oracle.py trust             # отчёт: кто HIGH, кто LOW
python3 tools/oracle.py pool --for T5-31  # активный пул CLOCK + window-eligible
python3 tools/oracle.py draw --for T5-31 --trust   # жребий только по HIGH+MID ≤ 80
```

Правила: window-eligible (просто не в окне) — НЕ «активный пул»;
активный пул CLOCK = HIGH первыми + MID до потолка 80 (приоритет MID:
никогда не катаны → реже всех → номер карты). LOW сидят до нового хита
или LAB. Дефолтный жребий без `--trust` — прежняя механика: паритет
прилавок↔печь↔сервис и золотые вектора нетронуты. Свежесть реестра
проверяет валидатор (№15).

## Калибровочный мост rating_truth_delta (аудит 5.3, волна 1)

Рейтинг — домен №1 по жалобам (T5-29: 17 ложных R+; T5-31: «много где»,
эталон В44 = слот P28 T5-31). Мост даёт машине 2-батчевый цикл честности:
машинный тир слота (slot_table новейшей квитанции) против послотовых
меток автора. Автор после рендера дописывает в вердикт
(verdicts/T5-NN.json, схема t5-verdict/1) опциональное поле — по СПОРНЫМ
слотам, не по всем 33:

```json
"rating_truth_delta": [
  {"slot": "P30", "truth": "R",  "note": "крупный статичный объект-панель — потолок R (В44)"},
  {"slot": "P28", "truth": "R+", "note": "эталон подтверждён"}
]
```

```bash
python3 tools/oracle.py rating-delta --batch T5-32
# → сошлось / ЛОЖНЫЕ R+ (машина завысила) / ПРОПУЩЕННЫЕ R+ (занизила) /
#   дрейф + группировка ложных по каналам delivery
```

Границы: инструмент — LAB-отчёт, НИЧЕГО не правит. Правка словарей
ratingTruth (specs/gates.json) — только по слову автора «калибровка
принята»; после правки перезапинить калибровку В43
(tests/python/test_t529_lessons.py). Это же точка входа контура обучения
оракула из вердиктов и рендеров (решение автора №6): каждый батч оставляет
след — либо метками в вердикте, либо словом «машина права, метки не нужны».
