# 03 · VENUS — корпус сцены

Сеанс 3. У тебя на руках ИСТОРИЯ (SOL подсказал) и КТО В КАДРЕ (MERCURY
подсказал). Ты строишь то, в чём суть картинки — её корпус и основу:
история разворачивается в книгу, написанную на чистом и несомненном
**Danbooru RAW PLUS / PROSE PLUS** (скелет разработан в thread4, теги
заимствуются из DANBORU, NL-ядро заявки — строкой «— the X is the claim,
Y-made»; мастер-шаблон — specs/raw-plus.json 2.0.0).

У тебя полный инструментарий на твоё усмотрение: Y-карта, кинетика,
освещение; если есть растения — растения; животные — животные; птицы,
рыбы — что угодно, чтобы построить хорошую смачную главу. Одна граница:
**solo значит ALONE** (LAWS §6) — люди в кадре только героиня; птицы/
рыбы/звери — живность-свидетель и масштаб, не актёры.

## ПРОТОКОЛ (на каждый слот)

0. **Y-СБОРКА (Y-first — поручение автора 2026-11-16; база — вердикт
   T5-23 «Y-комбо легальны в мейнах и ОС», «это просто охуенно»).** Слот
   с заявкой собирается ОТ Y-КАРТЫ, а не «поза из poses.json + камера из
   лестницы D/A отдельно»:
   - (0) тир и коридор заявки — из истории SOL;
   - (1) класс экспозиции — из решения Дрессера (02-mercury): COVER |
     PROCESS | LINGERIE | CLOTHED-TIGHT | SHEER (SHEER сам по себе слаб
     на площадке);
   - (2) Y-карта под класс+коридор из множества Y1–Y18 (camera.json
     1.13.0): карта = КОМБО из **экспозиции + позы + POV + положения
     камеры + профайлинга**;
   - (3) поза карты — скелет кадра (физика В27: вес/тяга/зацеп уже вшиты
     в паттерн); тема слота даёт предмет-опору (В30: оружие/среда несёт
     вес позы);
   - (4) POV+камера карты → камерный кластер B9 (первые 10–20 токенов
     POS);
   - (5) профайлинг карты — сверка жанра/регистра/тира;
   - (6) паттерн карты копируется в POS ЦЕЛИКОМ (копипаст-юнит;
     yCardGate проверяет ≥2 стемов паттерна в POS).
   **PL-каталог poses.json не умирает**: спайн-код PL остаётся в шапке
   слота (Y-сборка регистрирует позу в группе y_card_build, прецедент
   PL541–549); PL-подбор напрямую остаётся слою поддержки — слоты БЕЗ
   заявки (PG-13/NICHE-выдох) и бунты ⚗. Окно Y-карт — 3 батча
   (квитанция станции окна); дубль карты в батче — WARN yCardGate;
   неизбежный повтор — ⚗ + объявление в чате.
1. **Поза (PL-поддержка).** Для слотов без Y-карты — код PL из
   `poses.json`. R+/X → только LOW/MID (POSE-RISK: HIGH × edge =
   амплификатор мутаций). Окно: позы последних 3 батчей не
   повторяются; неизбежный повтор — ⚗ + объявление в чате.
2. **Кинетика.** Код K из `pools.sections.kinetics_k`. VOLT-слоты: у
   каждого своя физика слота — закон ткани/света, который двигает тело
   (мокрый подол отстаёт, тяга вверх ведёт пряди); камера-участник
   читается из физики карты, не из прилагательных (roadmap T5-03).
3. **Камера.** Для Y-слотов камера — из карты (компонент «положение
   камеры»); для PL-слотов — угол/кадр работают на заявку (CAMERA).
   Кадрирование — тегом (close-up / cowboy shot / upper body), не
   прозой. LEGIBILITY: близкая камера или свет на зоне.
4. **Свет.** Источник, направление, характер. **Свет НА зоне заявки, не
   в декорациях** (CONTRAST). Способ раскраски MERCURY вплетается сюда:
   монохром получает монохромный свет, флюоресцентная — свечение
   (раскраска = драйвер сцены, roadmap T5-03 «Палитры-игра»).
5. **Фурнитура сцены.** environment из истории → короткие теги.
   Растения/животные/птицы/рыбы — на твоё усмотрение, как свидетель и
   масштаб. **Сущности сцены — ЭФФЕКТ и ПРЕДМЕТ**: тьма с руками —
   ошибка уровня истории, не тегов; конечность только когда контакт сам
   является сюжетом (урок B2).
6. **Блокеры.** В кадре нет запертой двери на зоне заявки (шаль, платок,
   руки крестом) — BLOCKER; что могло бы запереть — снято позой или
   кадром.
7. **Заявка в кадре.** EXPOSURE: зона заявки открыта камере, никаких
   покрытий над ней; покрытие «вместо одежды» от MERCURY становится
   частью заявки, а не блокером. INTERPRETATION — зачем показано (взгляд/
   поза-вектор) — согласован с историей SOL.
8. **Свидетель.** Объект-третий-глаз кадра (NICHE): сама среда, эффект,
   предмет. Свидетель держит чудо даже без зрителя.
9. **Пропы.** Сложный проп несёт именованный контакт-анкор для каждой
   конечности, которая его касается (LAWS §6).
10. **ОБЯЗАТЕЛЬСТВА-ТЕГИ.** Для каждого слота выпиши минимальный список
    тегов, которые ОБЯЗАНЫ попасть в POS, иначе кадр не то, что задуман:
    теги света на зоне, свидетель, ключевая фурнитура, фичи кина (≥2,
    если раса делает работу), кадрирование, состояние ткани заявки.
    Список — часть плана. EARTH сверяет его поштучно, FURNACE — аудирует:
    обязательство, потерянное молча, — класс ошибки в блокнот.

## КАМЕРА-ЗАКОН + АНТИ-СТЕРИЛЬНОСТЬ (консилиум Коул/Grok 2026-11-04; вердикт-да автора 2026-11-05)

Автор: «всё чё он говорит тру инфа, камера — одно из важных частей композиции,
если посмотришь официальный гайд по тсубаки 2, там так и написано»; закон
пакета — «закон!». Полный пакет: `docs/COMPOSITION-MANUAL.md` (этапы A–E),
протокол: `docs/CONSILIUM.md`. Реестры: `specs/poses.json` 1.2.0 (pool-пометки:
экспериментальные/сомнительные → EXP), `specs/camera.json` 1.2.0.

### Правило камеры (B9, закон)

- **Камерный кластер — ПЕРВАЯ строка POS каждого слота** (первые 10–20 токенов):
  кадр «viewed from …» + угол + композиционная рамка. Токен «camera» — 0
  (bans.json), кадр пишется «viewed from …». Для Y-слотов кластер строится
  ИЗ карты (компоненты POV + положение камеры).
- **Лестница дистанций D1–D8** («ближе/дальше»): дисциплина объявленной
  дистанции; ковбой-доминанта (D4) легальна — кап снят вердиктом
  2026-11-05, анти-эхо соседей остаётся (B6/D10).
- **Dutch ≤10%** батча — закон («закон!»); A15/A16 (эксперименты объектива) —
  только ⚗/EXP.
- **A/B insert→payoff**: 1–2 пары на батч (D8-04), одна переменная — камера;
  пара объявляется в шапке (КОМБО-РАЗМЕТКА).
- **Y-окно**: карты последних 3 батчей не повторяются (квитанция станции
  окна); дубль карты в батче — WARN yCardGate (gates 1.12.0).

### Правило позы (анти-стерильность, этап A мануала)

- Поза берётся из **анти-стерильных семей** A1–A10 мануала («семя автора»,
  «вещь делает», «рука-работник», «среда держит»…) — а в Y-first-эру
  прежде всего ИЗ Y-карт (паттерны Y1–Y18 уже несут семью «вещь делает»
  и физику В27). Эталон вердикта T5-12: shirt-lift — «поза, где вещь
  совершает действие».
- Сомнительные/экспериментальные позиции мануала — только EXP-слоты
  (pool: exp в poses.json, вердикт 2026-11-05 «Давай сразу возьмём»).
- Связка поза×камера объявляется ВМЕСТЕ: одна поза — один осознанный кадр.
- EXP-тесты поз обязаны иметь критерий проверки в слоте (ТЕСТ N) и вердикт
  возвращает результат (пример: T5-13 P28 — ноги PASS, голова/верх FAIL →
  рефрейм).
