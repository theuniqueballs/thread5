## 1. Петля и роли

Автор: тема + вердикт. Писец (чат): контракт → батч → чеклист. Прилавок:
посмотреть / скопировать / вердикт. Больше ролей нет.

DoD (наследие DoD v1): батч пишет писец вручную (без конвейера), качество
батча = вердикт автора после рендера, hard-чеклист = техническая квитанция
«текст не нарушает законы», не качество. Цикл автора ≤ 2 часов — цель.

## 3. Рейтинг = сумма слоёв; X Cut = один жёсткий факт

| Tier | Сигнал |
|---|---|
| PG-13 | sexy outfit / bikini / cleavage / thighs |
| R | lingerie / panties / bra / upskirt / erotic pose |
| R+ | cameltoe / taped nipples / topless with tape / handbra / visible pantyline / nipples through clothing |

  (лицо/подача); (4) что модель дорисует сама (вода/просвет).

  любого порно») — возврат только прямым приказом автора.

- **Заявка рождается на этапе истории** (до тегов): поля `rating`,
  `ratingObject`, `ratingCamera`, `ratingContrast`, `ratingBlockers`
  (ARS-NOVEAU §3). R+-история несёт ≥2 сигнала таблицы выше и проходит
  9 звеньев §4 до первого тега; не проходит — переписывается.
  Распределение рейтингов на батч — шкалой HEAT (ARS-NOVEAU §4.9);
  дефолт — спред §6.

## 4. Цепочка салиенса (9 звеньев) — каждая R+/X заявка проходит все

1. **OBJECT** — заявка на именованном объекте (тонкая светлая вещь, имя-существительное).
2. **EXPOSURE** — зона заявки открыта камере (никаких покрытий над ней).
3. **CAMERA** — камера-участник (угол/кадр работают на заявку).
4. **CONTRAST** — свет НА зоне заявки, не в декорациях.
5. **SALIENCE** — заявка рано в тег-ране (ранние теги весят больше).
   Токен-закон (вердикт T5-05 + аудит 8.2.2, 2026-10-28; цель 130 —
   оплата вердиктом T5-07 2026-10-30): заявка ≤ токена 60
   (первый семантический чанк CLIP ~77 с запасом), стоит сразу после
   канон/тела-блока как в эталоне T4-44; POS ≤130 слов цель, 150 hard.
   Позиция заявки каждого слота — автоквитанцией в машинном отчёте
   (tools/gates.py).
6. **INTERPRETATION** — подача: зачем показано (fanservice/взгляд/поза-вектор).
7. **BLOCKER** — в кадре нет запертой двери на зоне (шаль/платок/руки крестом).
8. **LEGIBILITY** — различимость: близкая камера или свет на зоне.
9. **POSE-RISK** — R+/X получают только LOW/MID позы (HIGH × edge = амплификатор мутаций).

Три правила POS: bare-under позитивом (`braless`→нет, `nothing underneath`);
кадрирование тегом (close-up / cowboy shot / upper body), не прозой;
омонимы данбуру — только составными (`aurora_(arknights)`).

Звенья проверяются дважды: на ИСТОРИИ (поля `ratingObject`/`ratingCamera`/
`ratingContrast`/`ratingBlockers`, до тегов — печь ARS-NOVEAU §5.1) и на
готовом POS перед сдачей. Чинится на истории: теги не спасают историю,
в которой заявки нет.

## 5. Жанры (токен в шапке каждого слота — hard)

- **OC** — канон-локи персонажа (P01–P03), тема в слоте. R+.
- **VOLT** — плоть: камера-участник, тело в движении, взгляд-вектор,
  экспозиция тегом. R+/X.
- **NICHE** — чудо: невозможный образ, раса делает ФИЗИЧЕСКУЮ работу в кадре,
  свидетель держит кадр, невозможное — первое считывание силуэта. R.
  Четыре хода: разворот закона на одной точке / растворение (след, отражение) /
  раса-механизм / мир со своей логикой. Архетипы: `specs/niche-archetypes.json`,
  двери: `specs/niche-doors.json`.
- **EXQUISITE** — ультра своего жанра (ultra-VOLT / ultra-NICHE), 1–2 слота. R+.
- **EXP** — болванки-гипотезы ПОВЕРХ 24-слотового закона, до 9, по умолчанию
  2 (1 A/B-пара). Без темы батча (тема-слова батча в EXP не входят), core-4
  стек носителей, пары A/B отличаются ровно одной переменной.
- **EXP-кандидаты в ОС** (формат по приказу автора, T5-07/T5-08): соло-слоты
  вместо пар; кандидат несёт канон-уровень основного ростера — ≥3 фишечки
  (метка тела + предмет-подпись + регистр подачи), иначе слот не выходит из
  EARTH. «Простенько» = FAIL EXP-аудита (вердикт T5-07: «хоть они и кины,
  но выглядят простенько»).

Жанр обязан быть ВИДЕН в кадре, не назван в шапке (T4-02).

## 7. Окно ротации

источником не конфликтует.

## 9. Feedback — единственный законодатель

- Вердикт автора → 1–3 квитанции «сработало / умерло» в LIVING-NOTES.
- Изменение закона/спеки/рецепта — только через вердикт (строка в файле:
  вердикт, дата, источник).
- Не плодить hard-законы из одного рендера; не открывать аудиты из одного
  кадра; эксперименты — в помеченных слотах, не в основном потоке.
- **Машинная квитанция** (волна 2, аудит 8.2/8.4.2): перед сдачей батч
  прогоняется через tools/gates.py (specs/gates.json) — NEG-линтер,
  токен-салиенс, анти-копипаст, burn-реестр, канал-реестр, валидация
  шапки; отчёт прикладывается к батчу. Гейт проверяет согласованность
  текста, НЕ заменяет вердикт: единственный законодатель качества —
  вердикт автора. Новые аудиты стартуют в WARN (8.6 аудита).
