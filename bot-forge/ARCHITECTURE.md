# ФОРЖ v1.1 — АРХИТЕКТУРА ДОКУМЕНТА БОТА (новый пласт, с полного нуля)

Наследник ленивой версии (BotBible v1.0 → см. `LEGACY-NOTES.md`). Написан по
данным ресёрча Yodayo (см. `RESEARCH.md`) и по дисциплине thread5 (законы,
вердикты, квитанции, печь). Это не описание одного бота — это **конвейер
производства ботов**: каждый новый бот = один экземпляр этой структуры.
Живой пример — ростер `bots/B-01-mora/`.

Принцип thread5, перенесённый на текст: **чат — двигатель, файлы — память,
единственный законодатель — вердикт автора после живого прогона бота.**

---

## 0. Паспорт документа

| Поле | Значение |
|---|---|
| Код | FORGE-NN (экземпляры ботов: B-01, B-02, …) |
| Площадка | Yodayo Tavern (`yodayo.com/tavern`) |
| Движок | Nephra 24B · temp 0.9 · top_k 100 · top_p 0.9 · min_p 0.05 · rep_pen 1.1 · ~300 токенов ответ |
| Картинки | титульник/сцены — thread5 SPECIAL ORDERS (SO-NN, RAW+, титульник R+ Exquisite); состояния/фон/профильные — Image Editor (IE-пачка, R+) |
| Язык карточки | **EN only** — никаких русских символов в публикуемых полях (v1.3); копировалка FORGE подсвечивает кириллицу RU-бейджем; SO-документы не проверяются — их читает thread5, не бот |
| Обновление | только вердиктами автора после прогона (правило «фидбек — законодатель») |
| Формат чата Yodayo | `*действия курсивом*`, `"речь в кавычках"` |

## 1. Десять слоёв документа

Документ читается сверху вниз; каждый слой — отдельный блок с собственным
гейтом. Слои 01–07 — текст бота (уезжает в карточку Yodayo), слои 08–10 —
инфраструктура (не публикуется).

```
FORGE-NN
├── L00 PASSPORT        — паспорт: имя, слаги, категории, рейтинг, ссылки
├── L01 HOOK            — витрина: название-крючок + description-обложка
├── L02 CANON           — жёсткий канон (внешность + факты + канон-локи)
├── L03 ENGINE          — характер как механика: архетип, инверсия, векторы
├── L04 VOICE           — голос: речевые паттерны, лексикон, анти-флоры речи
├── L05 SCENARIO        — мир и стартовая точка (world_scenario)
├── L06 GREETINGS       — первые сообщения: основной + альтернативы (A/B)
├── L07 DIALOGUE        — example_dialogue: 3–4 пары, тон-локи
├── L08 LOREBOOK        — записи лорбука (только для миров)
├── L09 IMAGE STACK     — картинки: дорожка SO (thread5) + дорожка IE (Image Editor)
└── L10 OPS             — операционка: метрики, вердикты, ревизии, окно
```

Правило целостности: **слои не противоречат друг другу НИКОГДА**. Каждое
утверждение о персонаже живёт РОВНО в одном слое, остальные слои ссылаются
на него (код канона `C-NN`), а не пересказывают. Дубли — главный источник
плывуна.

## 2. Слои подробно

### L00 PASSPORT — паспорт бота

Задача: минута на решение «публиковать ли», всё административное — здесь.

```yaml
forge: B-01                      # код экземпляра
platform: yodayo-tavern
name: «…»                        # публичное имя (эмодзи-крючок + речь/вопрос)
nickname: «…»                    # короткое имя для чата и LLM
categories:                      # максимум 5, формула ресёрча:
  - Drama                        #   ядро
  - Roleplay                     #   режим
  - Scenario                     #   форма
  - Gender: Female|Male          #   аудитория
  - <фирменная>                  #   Monsters / OC / Tsundere / Yandere…
pov: both|male|female            # двух-POV — через нейтральный старт
content_rating: PG               # v1 всегда PG; R18 — отдельной ревизией
hashtags: [ … ]                  # до 5, слова-крючки поиска
images: [SO-06, SO-07]           # ссылки на Special Orders thread5
version: v1                      # растёт с ревизиями
status: draft|live|frozen
```

**Гейт L00:** имя не содержит имён известных персонажей (триггер площадки);
ник — одно слово; категории ≤ 5; теги — по одному слову (в копировалке
копируются поштучно, кнопка на каждое слово — v1.4).

### L01 HOOK — витрина

Задача: остановить палец в сетке ботов и получить клик. Данные ресёрча:
эмодзи-стопкер, прямая речь или вопрос-ловушка, обещание инверсии.

Структура блока — три варианта названия (A/B/C) + description-обложка:

```
НАЗВАНИЕ (A/B/C):
  A: 🏍-эмодзи + роль          — визуальный стопкер
  B: прямая речь персонажа     — голос в сетке
  C: вопрос-ловушка            — обещание интриги

DESCRIPTION (обложка, 400–700 знаков):
  1. Кто перед тобой — одна строка, конкретно.
  2. Ожидание аудитории («да-да, я знаю этот троп») —
  3. …и честная инверсия («нет. тут по-другому»).
  4. Правило interactions (что бот делает/не делает).
  5. Финальный крючок-провокация («Enjoy.» у Mallory — эталон).
```

Закон инверсии (из ресёрча, формула-победитель №1): **описание честно ломает
одно ожидание тропa — и не ломает больше ничего.** Одна инверсия = весь
маркетинг бота. Две — бот непонятен.

**Гейт L01:** описание ≤ 700 знаков; инверсия видна без знания канона;
последняя строка — крючок; нет спойлера движка (L03).

### L02 CANON — жёсткий канон

Аналог `canon_run` в thread5 (specs/special-roster.json): внешность и факты
фиксируются **однажды и дословно**, все картинки (SO) и текст ссылаются на
этот ран. Код `C-NN` присваивается каждому факту.

```yaml
canon:
  appearance: |                  # C-01 … C-09 — VERBATIM-ран для SO (POS)
    <дескрипторный ран: волосы, глаза, кожа, телосложение,
    фирменные предметы, нестираемые детали>
  facts:                         # C-10… — факты-несущие, не подлежат пересмотру
    - C-10: …
  locks:                         # канон-локи: НИКОГДА не меняется без ревизии
    - «цвета волос/глаз дословно»
    - «фирменный предмет всегда при ней»
  never_list:                    # анти-канон: что персонаж НЕ МОЖЕТ
    - …
```

Правила:
- `appearance` пишется **готовым POS-раном** (дескрипторы, не проза) — один
  блок обслуживает и текст чата, и все Special Orders без переписывания.
- Имя персонажа **не входит** в POS картинок (закон thread5) — только здесь,
  в nickname и в тексте чата.
- Два входа (двух-POV) фиксируются фактом, не отдельными канонами.

**Гейт L02:** ран ≤ 90 токенов в POS-виде; каждый факт с кодом; никогда-лист
≥ 3 пунктов; имя в POS отсутствует.

### L03 ENGINE — характер как механика

Задача: характер, который **выживает temp 0.9**. Не «она добрая, но
грустная», а машина с шестернями: у каждого входа — свой выход. Слои
`emotional_core` / `triggers` / `ladder` / `limits` — наследие BotBible
v1.0, влито в v1.1 (разбор — `LEGACY-NOTES.md`).

```yaml
engine:
  archetype: <один архетип>            # цундэру-тип, кукла, геката…
  inversion: <что ломает>              # ДНК бота — та же инверсия, что в L01
  emotional_core: >                    # формула BotBible, ОБЯЗАТЕЛЬНАЯ тройка:
    [базовая эмоция] + [искажение — эмоция как ПРАВИЛО/запрет, не черта]
    + [уязвимость]                     # «персонаж без ядра = пустой шаблон»
  drive: <чего хочет на самом деле>    # мотор всех реплик
  mask: <что показывает>               # публичная persona
  gap: <разрыв mask/drive>             # источник драмы; читается, не называется
  triggers:                            # 5 кнопок BotBible — ВСЕ расключены:
    - blush: <вход юзера> → <выход>    #   что вызывает смущение
    - dominance: …                     #   что вызывает включение власти
    - clinginess: …                    #   что вызывает липкость
    - loss_of_control: …               #   что ломает контроль
    - retreat: …                       #   что вызывает отступление
  vectors:                             # рёбра поведения: вход → выход
    - in: <действие юзера X>
      out: <стабильный ответ бота>
    - in: <действие Y>
      out: <стабильный ответ>
    - in: <действие Z>
      out: <стабильный ответ>
  ladder:                              # лестница эскалации BotBible: 4–6 уровней
    - "L1 дистанция — …"
    - "L2 лёгкое касание — …"
    - "L3 удержание — …"
    - "L4 прижатие — …"
    - "L5 признание — …"
    - "L6 NSFW-напряжение — …; R18 — отдельной ревизией"
  limits:                              # четвёрка BotBible (стены, не запреты)
    not_first: <чего не делает первым/первой>
    fears: <чего боится>
    stops: <что её останавливает>
    breaks: <что может её сломать>
  forbidden_moves:                     # что бот НЕ делает никогда (жёстко)
    - …
```

Векторы — главный инструмент против плывуна: у Nephra 24B маленький окно
внимания, три «вход→выход» ребра удерживают характер лучше абзаца эпитетов.

**Гейт L03:** архетип один; инверсия = инверсии из L01; emotional_core —
полная тройка; все 5 триггеров расключены; лестница 4–6 уровней; лимиты —
все 4 слота; ≥ 3 векторов; forbidden_moves ≥ 3; ни одно слово движка не
просачивается в L01 (нет спойлеров) — юзер разгадывает сам; persona-блок
EN без кириллицы (закон языка).

#### Блок persona — 13 секций (v1.4)

Помимо движка в L03 живёт публикуемый блок `persona` — полная развёртка
характера для поля `persona` карточки. НЕ абзац-саммари — многосекционный
документ вторым лицом («You are…»): **[1] IDENTITY CORE · [2] APPEARANCE &
SIGNATURE OBJECTS · [3] BACKSTORY · [4] PERSONALITY ARCHITECTURE · [5] CORE
WOUND · [6] CORE DESIRE · [7] CORE FEAR · [8] EMOTIONAL DEFAULT AT CHAT
START · [9] RELATIONSHIP TO USER · [10] VOICE CUES · [11] LIMITS RECAP ·
[12] WORLD ANCHORS · [13] NARRATION POV (CRITICAL).**
Дисциплина секций: черты — через поведение (CAPS-метка → что делает);
раны/желания/страхи — конкретные, не мелодрама; в [13] — запрет годмодинга
(действия в третьем лице, речь в первом, никогда не писать за юзера;
исключение — первое сообщение).

### L04 VOICE — голос

Задача: реплики бота узнаваемы в слепом тесте.

```yaml
voice:
  register: <регистр речи>             # «злой деловой», «мягкий приказ»…
  sentence_shape: <длина/ритм фраз>    # «короткие, рубленые, без канцелярита»
  tic: <одна речевая фишка>            # словечко/конструкция-визитка
  lexicon: [+]                         # слова, которые бот ИСПОЛЬЗУЕТ
  ban_lexicon: [−]                     # слова, которые бот НИКОГДА не говорит
  action_style: <стиль *действий*>     # что курсив показывает: руки, глаза…
  emoji_policy: none|borderline        # в чате Yodayo эмодзи почти не живут
```

**Гейт L04:** фишка одна (не три); ban-лексикон ≥ 5; стиль действий описан
физически (что видно), не психологически.

### L05 SCENARIO — мир и стартовая точка

Задача: юзер и бот в одной комнате с понятными стенами.

```yaml
scenario:
  setting: <место и время>             # конкретика: не «город», а «ларёк 24/7»
  relationship: <связь с юзером>       # roommate/клиент/сосед — один вход
  tension: <напряжение по умолчанию>   # что давит с первой минуты
  boundaries: <стены мира>             # что существует, что нет
  entry_points:                        # для двух-POV (если pov: both)
    - pov: male
      frame: <как юзер попал в сцену>
    - pov: female
      frame: <…>
```

Мир описывается **минимумом стен**: бытовые боты (формула-победитель №1 и №3)
живут в одной локации; RPG-миры (№4) требуют L08-лорбука.

**Гейт L05:** локация одна (для бытовых); relationship — одно предложение;
entry_points согласованы с greeting'ами (L06); world_scenario EN без
кириллицы.

Рядом с yaml живёт публикуемый EN-блок `world_scenario` — дословная строка
для поля `scenario` карточки (копировалка берёт её, а не внутренний yaml).
**Закон языка (v1.3):** всё, что мы вписываем в бота, — только английский;
никаких русских символов в сценарии, personality, creator notes и т.д.
Внутренние слои документа (комментарии, дизайн, OPS) — на русском, но в
карточку они не едут.
**Закон формата (v1.4.2):** реплики обособляются кавычками, всё, что не
реплики (действия, атрибуция), — звёздочками; ритм строки:
`"речь" *действие* "речь"`. Реплика внутри `*...*` (или смешанный абзац,
обёрнутый целиком: `*"речь" действие "речь"*`) — грубая хуйня и так нельзя;
копировалка ловит нарушение жёлтым ✱-бейджем.
**Закон типографики (2026-11-04):** em dash (—) в текстах ботов — отстой
(вердикт автора); везде — простой дефис (-): в публикуемых EN-полях и во
внутренних слоях документа. Новые тексты с «—» не пишутся никогда.

### L06 GREETINGS — первые сообщения

Данные ресёрча: greeting — король конверсии; альтернативные greeting'и
использует <1% ботов = бесплатный A/B. Формат площадки: `*действия*` + `"речь"`
— вердикт v1.4.2: формат верный; звёздочки — строго вокруг прозы, реплики
не оборачивать: "речь" *действие* "речь".

```yaml
greetings:
  main:                                # G-01 — рабочая лошадка
    words: 300-500
    beat_1: <место + конфликт в первом абзаце>
    beat_2: <момент-картинка (видеокадр)>
    beat_3: <реплика-визитка (голос L04)>
    beat_4: <крючок-провокация в финале>
  alt_a: <G-02 — другой регистр той же сцены>   # A/B-тест
  alt_b: <G-03 — другой вход (второй POV/время суток)>
```

Правила:
- Ровно **4 бита** в greeting: место → кадр → голос → крючок. Пятый бит — уже
  сценарий за юзера.
- Все три greeting'а несут ОДНУ и ту же инверсию (L01/L03), разные ракурсы.
- Финал — всегда реплика/действие бота, требующее ответа. Юзер не должен
  думать «что сказать» — он обязан реагировать.
- Мысли (inner thoughts) — опциональная механика: если введена, блок мыслей
  стоит В САМОМ КОНЦЕ сообщения — после всех действий и реплик, один раз;
  в persona директива мыслей — последняя секция (вердикт автора 2026-11-04:
  «прям в самом-самом конце»; на тесте автора — оставить или скипнуть).

**Гейт L06:** 300–500 слов каждый; бит-структура соблюдена; финал-провокация
есть; формат `*…*`/`"…"` не нарушен; ни один greeting не называет движок
(L03) прямо. **Регистр v1.4 (вердикт автора: «натянуто и глупо»):** бытовая
сцена — физика, предметы, тишина; юмор растёт из характера, без гэг-стопкранов
в первой строке; финальная реплика/вопрос стоит персонажу чего-то
(эталон-структура: сцена → ситуация → дорогой вопрос).

### L07 DIALOGUE — example_dialogue

Свободное преимущество: 90% ботов поле пусто, а 3–4 пары задают тон модели
лучше абзаца описания. Пишется ПЕРЕВОДЧИКОМ характера (L03→L04), не новыми
сюжетами.

```yaml
example_dialogue:
  - user: <типовой вход: подколка>
    char: <выход: вектор 1 голосом L04>
  - user: <вход: забота/наступание на gap>
    char: <выход: вектор 2, маска трещит — но не падает>
  - user: <вход: агрессия>
    char: <выход: вектор 3, escalation на низком регистре>
  - user: <вход: невозможно-бытовое>
    char: <выход: фирменная фишка (tic)>
```

**Гейт L07:** 4 пары; каждая пара демонстрирует один вектор L03; голос
L04 соблюдён; юзер-реплики — шаблонные (`{{user}}`), не сюжетные. **v1.4:**
реплики естественные, юмор из характера, панчлайн НЕ в каждой паре.

### L08 LOREBOOK — лорбук (только для миров)

Для бытовых ботов — пропускается с пометкой `n/a: domestic`. Для миров/RPG:
5–8 записей, каждая — триггер + 60–90 слов факта. Ничего из L02 CANON не
дублируется в лорбуке (канон всегда в контексте; лорбук — для фона мира).

### L09 IMAGE STACK — картинки бота

Две дорожки. **SO** — статичные картинки: производятся **в thread5** как
SPECIAL ORDERS (вне цикла батчей, тот же RAW+ формат). Один SO = одна
картинка. Ростер: канон бота регистрируется как OC автора
(specs/oc-canon.json) — не как гость. **Заказ адресуется чат-оператору
thread5** (отдельный чат, настроенный под рендер): SO пишется
самодостаточным документом, FORGE только регистрирует слот.

| Слот | Код | Назначение | Формат |
|---|---|---|---|
| Титульник | SO-AV | `thumbnail_photo` — сетка и карточка бота | портрет 9:16, лицо+верх, фирменный предмет, палитра канона; **рейтинг минимум R+ (эччи-укос), квалити Exquisite** — сетку продаёт картинка, не сюжет |
| Фон чата | IE-BG | `background_photos[]` — через Image Editor (BG-секции IE-пачки), не через thread5 | вертикаль 2:3–9:16, «no humans», низ кадра спокойный (под текст) |
| Сцена-greeting | SO-G1..3 | визуальные пары к greeting'ам (галерея `photos[]`) | сюжетные кадры битов L06; регистр — по сцене (PG…R+) |
| Профильные PNG | IE-PP | вторая картинка профиля — через Image Editor | белый фон, full body, бельё-константа канона, «красная от стыда, прикрывается» |

Законы переноса (thread5 → картинки бота):
- Hard-флоры §2 LAWS.md — без изменений (Genital lock, anti-loli, leak guard,
  milf-ban, X-изъят) — R+ держит бельевую границу: соски/гениталии — никогда.
- Canon-локи: `appearance` из L02 вшивается VERBATIM в первые ~10 токенов POS.
- Имя бота в POS не входит.
- Палитры/позы/носители — из спеков thread5 (palettes/poses/carriers), окно
  ротации считается по SO-слотам бота.
- РЕЙТИНГ-ПОЛТИКА v1.2 (вердикт автора: «боты идут в укос джага-джага, и мы
  не хуже»): SO-AV — минимум R+ с квалити Exquisite; SO-G — по регистру сцены
  (PG…R+) с блоком покрытия в NEG по §3 LAWS.md; фон чата — НЕ слот thread5
  (уехал в IE-BG).
- **NEG-адаптивность (наследие BotBible):** negative каждого слота реагирует
  на контент слота (shy → crazy eyes; tentacles → fused limbs; латекс →
  texture artifacts). Generic negative, кочующий между слотами, запрещён.

#### Дорожка IE — Image Editor (состояния, фон, профильные)

Фича Yodayo: картинка персонажа меняется от текущего состояния чата.
Базовая картинка редактируется Image Editor'ом, поэтому ST-промпты —
**только дельта**. Дорожка ведёт эччи-укос (v1.2): главная ось — шкала
одежды «одета → бельё», регистр R+ (explicit — никогда).

```yaml
ie_pack:                              # файл editor/IE-<CODE>.md на каждого бота
  delta_only: true                    # ST: база L02 НЕ повторяется — она уже на картинке
  no_name: true                       # имя не входит
  token_budget: { st: 45, bg: 90, pp: 60 }
  physics_only: true                  # только то, что видно
  rating: R+                          # эччи-укос: бельё/стыд/декольте — да; explicit — никогда
  clothing_ladder: true               # шкала одежды — главная ось состояний (одета → бельё)
  underwear_const: <канон-константа белья: цвет волос + акцент канона>
  binding: <каждое состояние привязано к триггеру/уровню лестницы L03>
  composition: <дельты одной ветки складываются через запятую, конфликтных нет>
  states: 3-4                         # v1.4 (эконом токенов): шкала одежды + 1–2 характерных
  transition_frames: 1-2              # v0.5: 1–2 ST помечаются «кадр Б» — полный кадр,
                                      # продолжающий кадр А (двухкадровый переход)
  bg_prompts: 1                       # BG-секция: полный промпт «no humans», низ кадра под текст
  profile_pngs: 1                     # PP-секция: белый фон, full body, бельё-константа, прикрывается
  reset: <возврат к базе — повторное открытие базового портрета, отдельного промпта нет>
```

Стартовый набор состояний любого бота (v1.4 — эконом: «состояний много =
дорого по токенам»): шкала одежды (2–3 ступени + бельё-константа) + 1–2
характерных состояния (страх / стыд / доминация). Итого 3–4 ST; пачка целиком
— 5–6 промптов (ST + 1 BG + 1 PP). Больше — только по вердикту автора.

#### Дорожка Motion — hover-луп заставки (кадр А → кадр Б)

Третья дорожка картинок: статичный рендер SO-AV оживляется при наведении
мышкой. Промпты живут в `motion/MOTION-<CODE>.md`; готовый рендер + промпт
уходят в img2video-нейронку. Формат: BASE («3d model, no 2d») + TAIL
(анти-морф-хвост) + NEG + пресеты + банк движений. Кадр SO-AV остаётся
статичным стоп-краном: луп делается ИЗ рендера, не вместо него.

**Закон бобов (вердикт автора 2026-11-04; цена урока ~2000 бобов за один
луп):** img2video не читает многодвижные промпты. **Один пресет = ОДНО
движение** (плюс максимум одно сопутствующее: дыхание, качание улики).
Камера стоит мёртво — push-in и прочая камерная работа только по вердикту
автора, не по умолчанию. Мигание света, блики и прочая «атмосфера» —
не движения, их из пресетов убирать (оставлять в банке).

**Кадр Б — двухкадровый переход-сюжет (механика с Нико, узаконена
вердиктом автора 2026-11-04):** автор залил в img2video две картинки —
кадр А (рендер SO-AV) и кадр Б (она в глазок пырит) — и получил
переход-сюжет: сначала кадр А, потом кадр уезжает в Б. «Получилось
мега круто», случайно. С этого дня это механика конвейера, не случайность:

1. **1–2 ST в IE-пачке помечаются «кадр Б»** — это НЕ дельта, а ПОЛНЫЙ
   кадр: канон-ран L02 verbatim + та же палитра/свет/ракурс, что у кадра А,
   + другое действие в той же сцене (композиция «продолжает» кадр А).
   Бюджет кадра Б — до 90 токенов (канон-ран + действие), ST-лимит 45
   на него не действует.
2. Кадр Б рендерится отдельной статикой (правила SO: RAW+, квалити кадра А,
   рейтинг — по сцене).
3. Луп: кадр А = стартовый кадр img2video, кадр Б = конечный; переход-сюжет
   нейронка собирает сама. Промпт лупа остаётся однодвижным.
4. **Порядок (закон «по порядку», вердикт автора):** кадр А (рендер SO-AV)
   → кадр Б (рендер ST-перехода) → motion-луп из них. Пропуск шага —
   бага сборки, не творчество.

**Гейт L09:** все SO ссылаются на C-коды L02; рейтинг каждой указан; SO-AV —
R+ Exquisite; имя вне POS; флоры в NEG каждого слота; NEG адаптен; в thread5 —
ТОЛЬКО титульник (v1.4: одна картинка — один заказ); IE-пачка: 3–4 ST (
из них 1–2 «кадр Б» — полный кадр) + 1 BG + 1 PP, каждый обычный ST — дельта
≤ 45 токенов; Motion: MOTION-док есть, пресеты однодвижные (закон бобов),
камера мёртвая, кадр Б отрендерен ДО сборки лупа (порядок: кадр А → кадр Б →
луп).

### L10 OPS — операционка

Память экземпляра: что с ботом делала площадка и что автор решил. Только
вердикты, только с датами.

```yaml
ops:
  published: <дата>            # статус live
  metrics:                     # снимки раз в неделю
    - date: 2026-11-05
      likes: n
      messages: n
  verdicts:                    # квитанции после живых прогонов
    - date: …
      verdict: «…»             # слова автора дословно
      receipts:                # 1–3 правки, вытекающие из вердикта
        - слой: L04
          change: …
  revisions:                   # версия растёт только здесь
    - v2: «что и почему»
  window: <что не повторяется в следующих ассетах>
```

Правила feedback-петли (наследие thread5 §9):
- Вердикт → 1–3 квитанции «сработало / умерло» — правки в слои.
- Не плодить жёсткие законы из одного прогона.
- Метрики снимаются, но законы из них не выводятся (метрика — диагноз,
  вердикт — лекарство).

## 4. Жизненный цикл

```
ресёрч (RESEARCH.md) → формула → FORGE-экземпляр (bots/B-NN-*/BOT-DOC.md)
  → L02 canon → L03 engine (ядро/триггеры/лестница/лимиты — ДО текстов)
  → L09 дорожка SO: титульник (R+ Exquisite) + сцена — заказ уходит
    чат-оператору thread5 → рендер (кадр А)
  → L09 дорожка IE: пачка состояний + BG-фоны + PP-профильные → прогон через
    Image Editor автором; 1–2 ST помечаются «кадр Б» → кадр Б рендерится
    отдельной статикой
  → L09 дорожка Motion: MOTION-док (однодвижные пресеты) → луп из кадра А;
    при двухкадровом переходе — из кадра А в кадр Б
  → L06/L07 тексты → публикация (v1)
  → живые прогоны → вердикты автора → квитанции в L10 → v2…
```

Скорость: экземпляр от нуля до v1 — одна сессия (скаффолд растера →
заполнение слоёв); картинка — один SO-цикл thread5; ревизия — одна
квитанция. Ничего не пишется «в стол»: каждое слово либо публикуется,
либо ждёт вердикта.
